📖 Manual de Implementación y Operación

Guía oficial para desplegar y configurar el agente en Windows, Linux, Oracle 23ai y GitHub.

1. Ocultar PR Banner 2. Token Git (PAT) 3. Script Oracle 23ai 4. Windows Setup 5. Linux Setup 6. Optimización DDL

1 Cómo Ocultar el Mensaje "Compare & Pull Request" en GitHub

Dado que este repositorio es un espejo de respaldo y las ramas desarrollo y produccion son independientes y nunca deben fusionarse, se puede desactivar la función de Pull Requests para ocultar permanentemente el banner verde de comparación:

  1. Entra a la configuración del repositorio en GitHub: https://github.com/vqorlando68/agente_backup/settings.
  2. En la pestaña General, desciende hasta la sección Features.
  3. Desmarca la casilla Pull requests.
  4. ¡Listo! Al no admitir Pull Requests, GitHub no volverá a sugerir fusiones entre ramas.
💡 Tip: Si en el futuro necesitas habilitar revisiones de código, puedes volver a marcar la casilla en cualquier momento.

2 Guía Paso a Paso para Generar el Token de Git (PAT)

El agente se autentica mediante un Personal Access Token (PAT) seguro, sin exponer contraseñas interactivas:

  1. Inicia sesión en GitHub y entra en Settings > Developer Settings > Personal access tokens > Tokens (classic).
  2. Haz clic en Generate new token > Generate new token (classic).
  3. Completa:
    • Note: Agente_Backup_Oracle
    • Expiration: No expiration (o según política empresarial).
    • Scopes: Marca la casilla repo (Full control of private repositories).
  4. Haz clic en Generate token al final de la página.
  5. Copia el token generado (inicia con ghp_...) y guárdalo de inmediato.

3 Script SQL para el Usuario de Oracle 23ai

Ejecutar con el usuario SYS conectado a la PDB orclpdb1 en cada base de datos (Desarrollo y Producción):

crear_usuario_backup.sql (Oracle 23ai) 
ALTER SESSION SET CONTAINER = orclpdb1;

CREATE USER USUARIO_BACKUP_AGENT IDENTIFIED BY "Backup_Ag3nt3_2026"
  DEFAULT TABLESPACE USERS
  TEMPORARY TABLESPACE TEMP
  QUOTA 0 ON USERS
  ACCOUNT UNLOCK;

GRANT CREATE SESSION TO USUARIO_BACKUP_AGENT;
GRANT SELECT_CATALOG_ROLE TO USUARIO_BACKUP_AGENT;
GRANT EXECUTE ON SYS.DBMS_METADATA TO USUARIO_BACKUP_AGENT;

5 Implementación en Linux (RHEL, Rocky, Ubuntu, Debian, Oracle Linux)

Bash Terminal 
# Clonar repositorio en /opt
cd /opt
git clone https://github.com/vqorlando68/agente_backup.git
cd agente_backup

# Crear entorno virtual e instalar dependencias
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Asignar permisos de ejecucion
chmod +x scripts/run_backup_desarrollo.sh
chmod +x scripts/run_backup_produccion.sh

Programar en el Cron del sistema con crontab -e:

crontab -e 
# Respaldo Desarrollo a las 04:00 AM
0 4 * * * /opt/agente_backup/scripts/run_backup_desarrollo.sh >/dev/null 2>&1

# Respaldo Produccion a las 04:30 AM
30 4 * * * /opt/agente_backup/scripts/run_backup_produccion.sh >/dev/null 2>&1

6 Características y Optimización del Agente

  • Detección Incremental (LAST_DDL_TIME): Solo descarga los objetos modificados. La ejecución pasó de 20 minutos a tan solo ~12 a 18 segundos.
  • Gestión de Objetos Eliminados (schema_objects_borrados/): Si un objeto es eliminado con DROP en Oracle, el agente lo mueve a la carpeta de borrados preservando la misma jerarquía.
  • Comentarios Incluidos en Tablas: Extracción automática de comentarios de tablas y columnas (COMMENT ON TABLE / COLUMN).
  • Formato Limpio de DDL: Sin palabras EDITIONABLE, sin propietario ni comillas en el encabezado CREATE.
  • Jobs DBMS_SCHEDULER: Extraídos con PROCOBJ y resguardados en schema_objects/jobs/.
  • Push 100% Desatendido: Uso de variables GIT_TERMINAL_PROMPT=0 y token seguro en memoria para evitar bloqueos interactivos.
